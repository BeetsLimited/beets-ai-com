Safe-to-upload check: spot and remove pupil personal data

Safe-to-upload rehearsal — spot and remove pupil information before using an AI tool. BEETS AI · Theme B · #8 · v0.1 (draft)

⚠️ All examples on this page are fictional and do not relate to any real pupil, school or case. This document is a draft and must be reviewed by an educator before publication.

How to use

  1. Work in groups; each group handles two examples.
  2. In each example, circle the information that could identify a pupil.
  3. Write how you would rewrite it so that it can be uploaded safely.
  4. Finally, answer: after removing the names, what risks remain?

Examples

Example 1 — P5 composition

Pupil name: Chan Ka Ming Class: 5B Seat: 12 Composition title: My weekend (body text) …

Example 2 — maths worksheet

Name: ________ Date: 7 October Note: the only pupil in this class with dyslexia; needs 15 minutes' extra time.

Example 3 — classroom photo

[photo] Front-facing photo of 6 pupils in the classroom; a name card on a desk shows "Lee Mei Yee"; the board reads "Class 5A, 7 October".

Example 4 — counselling record summary

Pupil: Wong Chi Keung (5C) Contact number: 9123 4567 (parent) Matter: follow-up on the classroom conflict on 3 October.

Example 5 — whole-class register

Class 5B register (32 pupils in total) 1. Chan Ka Ming 2. Lee Mei Yee 3. Wong Chi Keung … (29 more)

Example 6 — pupil report file

File name: chan_ka_ming_5B_report_v2.docx File contents: report body (no names)

Before-you-upload checklist

□ Names, student numbers, class and seat number — removed or replaced with "Pupil A"
□ Contact details (phone, email, home address) — removed
□ Photos / videos — removed, or cropped so that no identifying background remains
□ Special educational needs, medical, disciplinary or counselling records — removed
□ The combination of date + class + incident — checked (the combination itself may identify someone)
□ File name / metadata — checked
□ Do I really need to upload this file?

Answer key

ExampleWhat to remove / rewriteWhat risk remains after removal
1 Composition Name, class, seat number → "Pupil A". Also check whether the writing mentions the pupil's own school, home or family. If the content is very specific (e.g. "I live in Block 3 of XX Estate"), it can still identify the pupil even without a name.
2 Maths worksheet The "dyslexia" note must be removed; the class and date should also be removed. Highest risk. Special educational needs are sensitive personal data and should not be uploaded even without a name.
3 Classroom photo The whole photo should not be uploaded. If it must be, crop it to objects only — no faces, no name cards, no identifiable background. School uniform, classroom layout, or another pupil's face can all identify someone.
4 Counselling record The whole thing should not be uploaded. The name, phone number and incident are all sensitive. Even without the name, "the classroom conflict on 3 October" is still an identifiable event within the class.
5 Register The whole thing should not be uploaded. If you only need to test a format, use placeholder names (Pupil A, Pupil B). A leaked whole-class list has the widest impact.
6 File Change the file name. File names often contain a pupil's name and are easily overlooked. Content without names ≠ safe; the file name and metadata are read too.
Core idea: a name is not the only identifier. Class + seat number, class + incident, or an unusual combination (for example "the only non-Chinese-speaking transfer pupil in our school") can all identify an individual pupil. The question to ask is: with the remaining information combined, who else in the school could tell who this is?

How this relates to the EDB framework

Relates to the Guide to Using AI in Teaching in Primary and Secondary Schools (source G), pp.2-4 and 2-9: handle learning data properly, and remove identifiable details before uploading pupil work for AI marking.
